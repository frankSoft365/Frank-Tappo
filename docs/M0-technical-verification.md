## 目标

验证 PRD 中锁定的 5 项技术风险：

1. 双平台全局输入监听是否可用、macOS 辅助功能权限流程是否顺畅。
2. 透明 + 无边框 + 置顶窗口在两个平台的表现（macOS 是否出现黑底、无法穿透）。
3. 点击穿透（ignore cursor events）是否可靠、能否与托盘开关联动。
4. 输入事件到动画首帧的延迟。
5. 常驻资源占用是否满足性能预算。

> 分发渠道已定为官网安装包直装，App Store 沙盒限制不再构成风险，本项关闭。

## 已知问题

1. **macOS 权限模型**：rdev 的 listen-only 事件 tap 需要「输入监控」而非「辅助功能」；开发二进制每次重编译会改变 ad-hoc 签名，导致 TCC 授权失效。已加双权限检测与首启授权弹窗；正式发布需用稳定签名，并在文档中说明。
2. **空闲 CPU 超出预算**：常驻 CSS 动画（呼吸/耳朵/眨眼）持续 60fps 合成。M1 优化方向：窗口隐藏/睡眠时暂停动画、降低空闲动画帧率、减少合成层。
3. **窗口右下边距偏大**（约 48pt），定位逻辑需按 `visibleFrame` 精修（M1）。
4. rdev 0.5.3 引入的传递依赖 `block v0.1.6` 有 future-incompat 警告（不影响运行）。
5. macOS 屏幕录制权限限制导致无法自动截取原生窗口，原生视觉项依赖人工确认。

## 人工验证清单（需授权输入监控）

1. 打开「系统设置 → 隐私与安全性 → 输入监控」，勾选 `frank-tappo`：
   `/Users/frank/myCodes/Frank Tappo/src-tauri/target/debug/frank-tappo`
   （若列表中没有，点击应用内权限横幅按钮触发系统授权弹窗）
2. 回归应用：兔宝窗口应透明、始终置顶、位于屏幕右下。
3. 在任意应用敲击键盘：左手键位 → 左手拍击，右手键位 → 右手拍击；连续敲击应连贯跟手。
4. 终端（运行 `npm run tauri dev` 的窗口）应周期性输出：
   `[latency] samples=25 min=…ms p50=…ms p95=…ms max=…ms`
5. 托盘菜单：勾选「点击穿透」后鼠标可穿透兔宝；显示/隐藏、退出正常。
6. 静止 5 分钟：兔宝闭眼、耳朵下垂、出现 Zzz；任意输入唤醒。

## 结论与下一步

- Tauri 2 + rdev 在 macOS 15 / Apple M2 上可编译、可启动，窗口与托盘结构成立，未发现硬阻塞。
- M0 尚未完全退出：全局输入、点击穿透、延迟三项依赖辅助功能授权与人工交互确认。
- 下一步：用户完成授权 → 复测延迟与手势 → 跑一次 release 构建测资源 → 安排 Windows 真机验证。
